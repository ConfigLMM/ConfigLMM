# Frequently Asked Questions

**Q: Why name it "*Large*"? Why is "*L*" after Config in *ConfigLMM*?**

To be a pun of [LLM](https://en.wikipedia.org/wiki/Large_language_model) — and like a language model,
you don't need to write every single detail. Also *ConfigLMM* is definitely smarter than LLMs :)

Another reason: it really is quite *Large*/big as a project — there is a lot of ground to cover.

---

**Q: I already have an infrastructure deployer/orchestrator that I love and don't want to change — is this useless for me?**

Not necessarily. You can use `configlmm build` to generate configs and then use your own orchestrator for
actual provisioning/deployment (and apply additional customization on the built configs).

**Q: Are you crazy/insane?**

Yes :) But maybe everyone is — by having to learn hundreds of different tools, each with different
versions, dozens of incompatible flags, and multiple configuration file formats.

The complexity of the current ecosystem is insane, and the number of different tools only keeps growing.

Can you count how many different tools/programs you've used today? This week? This month? In a year?
In your whole career? *ConfigLMM* aims to reduce that cognitive overhead.
